## Typed metadata

Define your metadata shape once in a `.d.ts` file included by your app's `tsconfig.json`:

```typescript
import "js.foresight"

declare module "js.foresight" {
  interface ForesightRegister {
    meta: {
      href: string
    }
  }
}
```

Registration options, callback state, events, devtools, and all framework bindings use this shape automatically. No generics are needed.

```typescript
import { ForesightManager } from "js.foresight"

ForesightManager.instance.register({
  element: document.querySelector("a")!,
  meta: { href: "/about" },
  callback: state => {
    console.log(state.meta.href.toUpperCase())
  },
})
```

Without augmentation, `ForesightMeta` defaults to `Record<string, unknown>`. Metadata remains optional and defaults to `{}`. Unregistered framework snapshots also contain `{}`, so use optional fields such as `href?: string` if you read them before registration or register elements without metadata. Augmentation only changes types, it does not validate metadata at runtime.

## Most Used Internal types

### ForesightElementState

This is the main type used in ForesightJS: the flat, immutable state snapshot of a registered element. Your [callback](#foresightcallback) receives it, most [events](../events.md) carry it as `state`, and `register()` returns it (plus a few functions, see [ForesightRegisterResult](#foresightregisterresult)). The reference is replaced on every logical change, never mutated. Geometry-only changes use [ElementBounds](#elementbounds), on their own subscription channel. Scrolling can still change logical state, such as viewport visibility or prediction status.

```TS
type ForesightElementState = {
  id: string // unique id assigned during registration
  name: string // name visible in the devtools
  meta: ForesightMeta
  hitSlop: Exclude<HitSlop, number> // normalized hit slop applied to this element
  isLimitedConnection: boolean
  isIntersectingWithViewport: boolean
  isRegistered: boolean
  isActive: boolean
  isParked: boolean // detached from the DOM, kept registered but inactive until it reconnects
  isEnabled: boolean
  isPredicted: boolean
  isCallbackRunning: boolean
  hitCount: number
  registerCount: number // amount of times this element has been (re)registered
  durationMs: number | undefined // duration of the most recent callback run
  status: "error" | "success" | undefined // status of the most recent callback
  error: string | null
  reactivateAfter: number
}
```

See the [registration return value](../configuration/registration-options.md#registration-return-value) for what each field means.

### ElementBounds

The element's geometry: its measured rect and the [hitSlop](../configuration/global-settings.md)-expanded rect used for interaction detection. Visible elements' position and size changes are published on a separate channel (`getBounds`/`subscribeToBounds`) and kept out of `ForesightElementState`, so geometry-only updates do not notify state subscribers.

```TS
type ElementBounds = {
  originalRect: DOMRectReadOnly // as returned by getBoundingClientRect()
  expandedRect: Readonly<Rect> // originalRect + hitSlop
}
```

### ForesightRegisterResult

What `ForesightManager.instance.register()` returns: the element's state at registration time plus control functions.

```TS
type ForesightRegisterResult = ForesightElementState & {
  unregister: () => void
  subscribe: (listener: () => void) => () => void // logical state changes; returns an unsubscribe function
  getSnapshot: () => ForesightElementState // current state snapshot, stable reference across scrolls
  subscribeToBounds: (listener: () => void) => () => void // geometry changes (every scroll/resize tick)
  getBounds: () => ElementBounds // current geometry snapshot
}
```

### CallbackHitType

```typescript
type CallbackHitType =
  | { kind: "mouse"; subType: "hover" | "trajectory" }
  | { kind: "tab"; subType: "forwards" | "reverse" }
  | { kind: "scroll"; subType: "up" | "down" | "left" | "right" }
  | { kind: "touch"; subType?: string }
  | { kind: "viewport"; subType?: string }
```

### CurrentDeviceStrategy

Represents the current input method being used. ForesightJS automatically detects and switches between strategies.

```typescript
type CurrentDeviceStrategy = "mouse" | "touch" | "pen"
```

### ForesightManagerData

Snapshot of the current ForesightManager state, including all [global settings](../configuration/global-settings.md), registered elements, and interaction statistics. This is primarily used for debugging, monitoring, and development purposes.

This data is returned in the [`managerSettingsChanged`](../events.md) event or by calling [`ForesightManager.instance.getManagerData`](../debugging/static-properties.md#foresightmanagerinstancegetmanagerdata) manually.

```TS
type ForesightManagerData = {
  registeredElements: ReadonlyMap<ForesightElement, ForesightElementState> // See above for ForesightElementState
  globalSettings: Readonly<ForesightManagerSettings> // See configuration for global settings
  globalCallbackHits: Readonly<CallbackHits> // See above for CallbackHitType, this is that but all of them combined
  eventListeners: ReadonlyMap<keyof ForesightEventMap, ReadonlySet<ForesightEventListener>> // All event listeners currently listening
  currentDeviceStrategy: CurrentDeviceStrategy
  activeElementCount: number
  parkedElementCount: number // elements detached from the DOM, waiting to reconnect
  loadedModules: ForesightModules // which handlers/predictors are lazily loaded
}
```

## Helper Types

### ForesightCallback

The callback function type used when registering elements. Receives the [`ForesightElementState`](#foresightelementstate) of the element that triggered the callback.

```typescript
type ForesightCallback = (state: ForesightElementState) => void
```

This is useful when registering multiple elements with a shared callback, as you can identify which element triggered it:

```typescript
const myCallback: ForesightCallback = state => {
  console.log(`Triggered by: ${state.name}`)
}
```

### ForesightRegisterOptionsWithoutElement

Useful for if you want to create a custom button component in a modern framework. And you want to have the `ForesightRegisterOptions` used in `ForesightManager.instance.register({})` without the element as the element will be the ref of the component.

This type is the options object you pass to the [`useForesight`](../react/useForesight.md) hook in React, the [`useForesight`](../vue/useForesight.md) composable in Vue, and Angular's [`[fsForesight]`](../angular/directive.md) / [`ForesightService`](../angular/foresight-service.md) APIs.

```typescript
type ForesightButtonProps = {
  registerOptions: ForesightRegisterOptionsWithoutElement
}
```
